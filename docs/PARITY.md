# Parity with herdr

`tmux-agent-wizard` targets feature parity with [herdr](https://herdr.dev) v0.9.3
(socket protocol 22, 2026-09-29) for people who stay on tmux, plus two files from herdr
master (`d6b40d4`, 2026-10-01): the Codex and Pi manifests, where a Codex at rest reads idle
again; and four manifests from master at `5608de0608` (2026-10-23), see "herdr v0.9.4 and
master's detection changes" below. The reference copies of herdr's own files under
`third_party/herdr/` are v0.9.3's, with `manifest.rs` and the Pi manifest from master
(`d6b40d4`), and the Claude, Codex, Grok and Antigravity manifests from master
(`5608de0608`).
`taw session snapshot` reports protocol 22, as the vendored schema does.
`[plugins] compat_herdr_version` is `0.9.3`. A row labelled with a v0.9.2 change may have
taken it from master (`0d5d6f1`, 2026-09-27) before the release.

herdr is a standalone multiplexer that *owns* agent terminals; this project is a tmux
plugin plus one binary, `taw`, that *observes and drives* the tmux you already run.
Anything herdr can do that tmux genuinely cannot is listed here as `✗`, not silently
dropped.

The rule is: **parity first; a refinement beyond herdr is made when users need it or it is
a simple fix, and every one of them is listed in the README's
[Beyond herdr](beyond-herdr.md)** and in the popup ledger below.

> Rows below describe herdr-equivalent *behaviour*. Where that behaviour is exposed
> as a `taw` CLI verb, see `taw --help` (or `docs/ARCHITECTURE.md`'s module map) for
> the exact command.

This file has eight parts. **Parity** is what matches, and how. **Popup ledger** maps
each herdr and tmux-session-wizard interaction onto the tree popup. **herdr v0.9.0**
is the status of each item in that release's port set. **herdr v0.9.1 to v0.9.3, and master**
lists what has been taken from later than that. **herdr v0.9.4** lists what has been
taken from that release. **Known divergences** is where
an implemented verb behaves differently from herdr's. **Structural gaps** is the short
list of things tmux cannot express, each with why and the closest thing you can do
instead. **Pinned** is what is deliberately not being worked on.

## Parity

| herdr | tmux-agent-wizard | status | how |
|---|---|---|---|
| detection: manifests, remote updates, local overrides, `agent explain` | same engine, the same 22 bundled manifests, ported unit tests | ✅ (plus supplements) | herdr's manifest engine (`src/detect/`) is a faithful, function-by-function port; identity (every name herdr's identity table knows, `opencode2` included, OpenCode 2's preview binary, which no manifest lists, so `identity.rs` names it itself), regions, rules, `min_engine_version`, and remote-update precedence all match, and herdr's own manifest tests are ported with it, down to the three engine-contract tests that v0.9.2 added. On top of it, and never inside the vendored files, `src/detect/supplements/<agent>.toml` appends taw's own rules after the upstream ones, so at equal priority upstream still wins: six for Claude Code and one for Codex, listed in README "Beyond herdr". `[detection] supplements = false` turns them off; `taw manifest show <id>` tags every rule `source: "manifest"` or `"taw"`. The watcher's state arbitration follows herdr's pane detection task as v0.9.1 and v0.9.3 have it (v0.9.3 adds the completion guards, see the next row, and a startup check for a Codex that reads `unknown`, which taw does not take): a 300 ms read cadence (100 ms during a hold), output only making a pane eligible for a read, the hold on the way from working to plain idle (3 confirmations or 700 ms), the 3 s startup grace, exit-idle-first and 5 identity misses; an agent that takes the pane does not read the title or OSC progress the last one left, and a name goes with the agent it was given to. Identity also reads a container runtime's arguments, beyond herdr: when the pane's foreground command is docker, podman, nerdctl, Apple's container or sbx, the watcher reads its exact arguments once for each process (from the system, `ps` only when that fails) and takes the agent it names, marks the pane `@agent_container`, and reads the state from the screen as usual; an agent taw started in a container through a profile is marked with the profile (`@agent_sandbox`), and restore brings it back through that profile, with the id its integration reported from inside; one taw did not start is not resumed, never outside its container (README "Agents in a sandbox"). `done` and `seen` follow herdr's completion rule (next row) |
| an agent started inside a container from a pane | recognised from the container runtime's arguments | beyond herdr | when the pane's foreground program is Docker, Podman, nerdctl, Apple's `container` or `sbx`, taw reads the arguments it was started with, once for each process that comes to the front of the pane (exactly as the system has them on macOS and Linux, `ps`'s line where it will not say), and takes the agent as the program the container runs: the word after the image, the word after `run` for `sbx`, or a command of the script a shell in the container runs. It has to be the agent's own executable, so an image, a container, a directory or a flag value that happens to be called `claude` is not the agent. The pane is then that agent's: its state is read from the screen with the agent's own rules, `@agent_container` names the runtime for a status line or a pane border, and the mark goes when the runtime does. The arguments can hold credentials, so nothing of them is kept or logged. Three limits: an agent in a container taw did not start (one you typed by hand) comes back from `session restore` as a plain shell, its conversation not resumed, and never outside its container (one taw started through a profile does come back, see the next row); only the command line is read, so an agent typed inside `docker exec -it box bash` is not found; and a container whose script carries on after its agent quits keeps reading as that agent, idle, until the runtime exits (README "Agents in containers") |
| an agent in a sandbox (herdr has none) | `taw sandbox`, typed in a pane, runs any agent in a container there through a profile, a plain script (taw ships one, `default`); `taw sandbox new` and `taw sandbox list` make and list profiles; `taw agent start --sandbox` does it for an agent or a script | beyond herdr | herdr has no sandbox of its own. An agent run in a container of a shell function's making has no mark, and its conversation's id stays inside the container, where no restore can read it. Here 📦 marks the agent in the popup, in a container that taw started, or saw start, and restore brings one taw started back inside its sandbox, never outside, and in its conversation once the agent's hook is installed (README "Agents in a sandbox") |
| states working/blocked/idle/done/unknown, seen semantics | `@agent_state` + `@agent_seen` + `@agent_acquiring` | ✅ | five states, and `done` vs `idle` follows herdr's completion rule with the guards herdr v0.9.2 added to it (#4457; `src/app/actions.rs` and `src/terminal/state.rs`, v0.9.3): a completion (`idle` after `working` or `blocked`) is `done` when you are not looking at the pane as it happens and `idle` when you are, and a glance earlier in the turn does not count. `unknown` to `idle` is not a completion, and neither is the first `idle` of an agent taw has just taken (a new agent the watcher finds, one `agent start` launched or a restore resumed, or one whose session another replaced) until it has been seen working, unless it exited: a trust question asked at startup and answered later is the agent becoming ready. A change of session (Claude's `/clear` and `/resume`, Pi's `/new`) or of agent, whatever the pane's state, marks the pane seen, turns a `done` back into `idle`, and drops a notification still waiting out its delay (the row of herdr v0.9.2's #4457 below, and "Known divergences" for where the timing differs). Looking is herdr's active tab with an outer terminal not reported unfocused: the pane's window is the active window of a session with a client attached, and not every terminal attached to that session has reported losing focus. A terminal reports its focus to tmux only when `focus-events on` asks it to, and taw reads the answer only then, on tmux 3.6+ (verified on 3.6b); otherwise nobody's focus is known, and that counts as looking, as herdr counts a terminal that never reports its focus. `done` is herdr's unseen idle written as a state of its own, and tmux's focus hooks, or the next read that finds you looking at the pane, are what mark a pane seen |
| sidebar (agents, spaces, rows config, sort) | popup TUI + opt-in status token | ✅ (translation) | herdr's always-visible sidebar becomes a `display-popup` (see "Structural gaps") plus the opt-in `#{@agent_wizard_status}` token for a permanent-but-compact summary. Its two panels become one tree (sessions, then the panes under each, then closed worktrees) in tmux's order; herdr's own flat agent list is `f`, ordered by `[ui] agent_panel_sort`. Row templates, `rows_by_agent` and `row_gap` are unchanged, and `[ui.sidebar.sessions]` is accepted as an alias of `[ui.sidebar.spaces]`. See the popup ledger below for the per-interaction mapping |
| goto / workspace pickers, help, settings overlays | in the popup | ✅ | one `/` filter covers both pickers (fzf syntax over the whole tree, matching agents, sessions, paths, branches and each agent's state word and title as its row draws them); `?` is help, `o` is the settings overlay, now called options |
| agent view queries (`agent.view.set`/`clear`) | `taw agent view set`/`clear`, over the global `@agent_wizard_view` option | ✅ | the whole declarative query: `all`/`any`/`not` over `eq`/`in`/`exists`, the same fields and limits, context values for the current workspace and tab, and `sort`, which replaces `[ui] agent_panel_sort` for as long as the view lasts without rewriting the config. `--params` takes the entire herdr params object for a caller that already has one. It projects the Agents panel and the goto picker's agent rows only: `agent list`, notifications and detection keep seeing every agent, exactly as in herdr. The agent order a view installs is the Agents *panel's*, which `taw` already owns; it is not the workspace ordering under "Pinned" |
| toasts (`off`/`herdr`/`terminal`/`system`), `delay_seconds`, background-only | `display-message` / OSC / OS notifier | ✅ (position ✗) | all four delivery modes and the background-only gate, which counts a pane whose terminal has lost focus as background (tmux 3.6+ with `focus-events on`; see the states row) for every mode, where herdr still keeps its own in-app toast off the active tab and sends only its OS and terminal notifications; screen position has no tmux equivalent (see "Structural gaps"). `[ui.toast] done_delay_seconds` (default 5) adds a separate, longer wait for *done* toasts; `0` restores herdr's single-delay timing. The popup is sized to leave the status line visible, so `herdr` delivery lands there with the popup open exactly as it does with it closed |
| sounds, per-agent mute | ✅ (no bundled sounds) | ✅ | `afplay`/`paplay`/`aplay`; herdr ships sound files, this project asks for paths (see "Structural gaps") |
| `open_notification_target` | `prefix + O` (configurable) | ✅, extended | `taw notification open-target`, bound to `@agent-wizard-notification-key`, and reachable inside the popup through the prefix chord. herdr's key focuses the notification that is on screen; taw walks "next up" instead, the same rule as the popup's `Tab`: the next agent that needs you after the pane you are in, in tmux order, else, with none that does, the next agent of any kind, and it reports `not_found` (`taw: no agents` on the status line) only when no pane holds an agent. The latest notification is deliberately not a step of its own: a request is an agent that needs you, so it is in the first group anyway |
| CLI verbs and record shapes | the `taw` argv CLI, same JSON records | ✅ CLI · ✗ socket | most of herdr's socket methods are reachable over argv, with herdr's own field names: 81 of v0.9.3's 102 have a verb, and the other 21 are listed, each with its reason, in `docs/COMPAT.md`, "Socket methods taw has no verb for" (among them `server.ssh_agent.register`, which keeps a forwarded ssh agent working in herdr's remote panes, and is not ported). `pane.clear` has a verb that is taw's own, `taw pane clear`, which clears less (the row of v0.9.2's #4383 below, and "Structural gaps"). herdr removed `pane.graphics.*` in v0.9.2. The *transport* is the gap (see "Structural gaps") |
| plugin lifecycle events (19 names) | tmux hooks + CLI verbs + the watcher | ✅ | every name in `third_party/herdr/reference/event-names.txt` fires; `docs/COMPAT.md` has the table of what triggers each |
| a command of your own on an event (herdr runs a command on an event only through plugins) | `[hooks]` in `config.toml`; `taw hooks list`, `test` and `log` | beyond herdr | herdr tells its events to plugins, which are packages with a manifest, and its toasts stay on the machine you are on. Under `[hooks]` each key here is an event name and each value a command of yours, or a list of them, run through `sh -c` in the background with the details in `TAW_*` environment variables and the event's JSON on standard input. The events are the 19 a plugin hears, `agent.blocked`, `agent.working`, `agent.idle` and `agent.done` (the moments an agent goes into that state, whether the watcher read it off the screen or its hook reported it) and `notification`, which fires exactly when a toast would, after the same delay and never for a pane you are looking at, so a push to a phone is one line (README "Notifications on your phone"). `pre_close` and `pre_worktree_remove` can say no: taw waits for them, and a non-zero exit, or running past `[sessions] hook_timeout_seconds`, refuses the close or the removal with the error code `hook_refused`. A close taw is not asked about is not seen: tmux's own `prefix + x` and `prefix + &`, and a process that ends by itself. README "Hooks" has the event table, the variables and `taw hooks test` |
| `client.window_title.set` / `clear` | `taw terminal title set` / `clear` | ✅ | tmux's `set-titles`/`set-titles-string` on the attached client |
| `session.snapshot` | `taw session snapshot` | ✅ | one bootstrap read of every workspace, tab, pane, layout and agent record, in herdr's own shape, the CLI equivalent of `herdr api snapshot`. A one-time read in both: herdr's socket page (v0.9.2 on) tells a client to subscribe to events first and then reconcile through authoritative reads such as this one; here the events are the plugin event hooks |
| `layout.export` / `apply` / `set_split_ratio` | `taw layout export` / `apply` / `set-split-ratio` | ✅ | tmux's own `window_layout` string is the export format, `select-layout` applies it, and `resize-pane` sets a split ratio |
| `popup.close` | `taw popup close` | ✅ | the popup is a `display-popup`, so this closes it on the client the way herdr's method does |
| `config check`, `config reset-keys` | `taw config check`, `taw config reset-keys` | ✅ | `reset-keys` removes the `[keys]` table from `config.toml` and leaves every other byte alone, so the popup falls back to its preset |
| `[keys]` bindings | `[keys]` for the popup's own keys | ✅ (translation) | herdr binds its whole UI; tmux owns every key outside a popup, so `[keys]` here binds the 18 actions *inside* it, and the two prefix keys stay `@agent-wizard` tmux options. `preset = "modal" \| "search"` picks the base map, per-action entries override it, and herdr's own action names (`goto`, `workspace_picker`, `new_workspace`, `rename_workspace`, `close_workspace`, `next_workspace`/`previous_workspace`, `settings`) are accepted as aliases. Key specs are herdr's grammar. `prefix+…` is refused, since that chord is tmux's, and `open_notification_target`'s key is read from `@agent-wizard-notification-key` rather than from this table, so it works inside the popup and out, after either of tmux's two prefixes, `prefix` and `prefix2` |
| `server reload-config`, `reload-agent-manifests`, `update-agent-manifests` | `taw config reload`, `taw manifest reload`, `taw manifest update` | ✅ | there is no server holding config, but the `pipe-pane` watchers are long-lived and each holds its own copy, so these re-read the file in every live watcher rather than restarting anything. The popup re-reads on its next tick regardless |
| agent skill | `taw skill` | ✅ | prints the adapted `SKILL.md` (`include_str!`), guarded on `$TMUX` instead of `HERDR_ENV` |
| integrations (18 agents) | 18 hook targets | ✅ | the same 18 targets herdr installs into (Letta, which herdr lists last and calls experimental, is last here too), each writing a `taw` hook script and registering it in that agent's own config; README "Integrations" has the per-agent table. herdr now has two kinds of support, by herdr (these 18) and by the agent (Command Code, Crush, Kiro CLI, Muse Code and Prime Agent report to herdr themselves, where `HERDR_ENV=1` and `HERDR_PANE_ID` and `HERDR_BIN_PATH` are set): `@agent-wizard-herdr-env`, off by default, gives tmux's global environment those three (`HERDR_PANE_ID=%calling`, a word taw's pane verbs read as `$TMUX_PANE`), so an agent that follows herdr's guide reports to taw from any pane created after the plugin loads. It is off because `HERDR_ENV=1` tells every herdr-aware program it runs inside herdr. No `HERDR_SOCKET_PATH` (taw has no socket: an agent that reports through the socket reports nothing), and a sandboxed agent cannot reach the host's `taw`; README "Agents that report to herdr themselves" |
| plugins (manifest, actions, events, panes, startup, trust preview) | ✅ CLI-driven plugins · ✗ raw-socket plugins | partial | same manifest format, env vars, and trust-preview gate; see `docs/COMPAT.md`. herdr removed `pane.graphics.*` in v0.9.2, so a plugin no longer has graphics methods to miss here |
| plugin discovery (`plugin search`, the marketplace page) | ✗ | ✗ | herdr's discovery is a *web* marketplace listing GitHub repositories tagged with the topic `herdr-plugin` (`third_party/herdr/reference/plugins.mdx`); herdr ships no CLI verb for it, so there is no command shape to port and no output to mirror. Searching GitHub from `taw` would be a new feature rather than parity, and would add a `gh` dependency (taw goes online only for the reasons the README's "What goes online" lists). Install by spec instead: `taw plugin install <owner>/<repo>[/<subdir>][@<ref>]`. `taw plugin list` covers the installed side |

A worktree whose session is not running is a `◌` row under its parent session: `Enter` restarts it, `x` removes it |
| restore after restart + native agent resume | snapshots + resume | ✅ | `taw session save`/`restore` (a plain restore after a tmux server change also finds the previous server's last layout: README "Beyond herdr"; in a saved session that is open it adds the windows whose agent conversation runs nowhere in the server and changes nothing already open, and with no server it starts one), and `[session] resume_agents_on_restore` for every integrated agent whose own CLI has a resume flag (all 18, Letta included). pi and omp resume from their saved session *path* when no session id was reported; herdr prefers the path outright, taw prefers a valid id and falls back to the path, which never changes a pane that already resumes. A command an agent reports for itself wins over taw's own for that agent, each session is resumed in one pane of a restore, a pane whose saved directory is gone is not resumed and keeps its directory and session in later saves: the rows of v0.9.1 and v0.9.2 below. | a crash of the multiplexer itself | n/a: herdr's server is its own program | taw only (macOS) | when the plugin loads on a new tmux server and the last one on the same socket is gone, `taw server started` copies that tmux's crash report from `~/Library/Logs/DiagnosticReports` into `<state>/tmux-crashes/` and tells you once where it is and that `taw session restore` brings back what it had. It waits up to two minutes for the report, matches it by the dead server's pid, never overwrites a file, and says nothing for a server that was killed or ended with its last session. README "Save and restore" and "Beyond herdr" |
| starting an agent in a pane, and a restore's resume commands | `taw agent start`, `taw session restore` | ✅, plus a wait | herdr types into a shell here too: `agent start` wants the pane at its interactive shell prompt and answers `agent_pane_busy` at once when it is not, and a restore spawns a shell and sends the resume command without waiting for a prompt. taw waits first, because a shell that is still starting hands what is typed to whatever reads the terminal first, and a startup question, mise's "Trust them?" for one, would be answered by the keys of a command. It waits until the pane's shell is at its prompt by herdr's own idle-shell test (the one the watcher uses: the terminal's foreground group is led by the pane's process, holds nothing else, and the process has a shell's name), then for the screen to stay unchanged for 300 ms, for 15 seconds at most. A shell that does not come to its prompt is left alone: `agent start` fails with `shell_not_ready` and types nothing, and a restore says in its plan, and in `not_resumed`, which pane to run which command in by hand. A pane in a tmux mode (copy mode, the clock, a chooser) or with its input off takes none of what is typed, so both give it up at once, with the reason, and leave it in its mode; `agent prompt` and `agent send-keys` refuse it the same way. `--timeout` is one budget for the whole verb. A restore also reports which windows it made and which it did not, each by the number it had when saved, selects windows by their own ids so that a pane, a window or a session closing under it stops only what it cannot finish, and holds autosave off while it runs (`@agent_wizard_restoring`) so the tmux hooks cannot save a half-made layout over the snapshot it reads. A pane whose saved directory is gone is typed nothing at all (tmux opens it in your home folder, where herdr starts no shell), and the plan says which directory, with the command to run once it is back; README "Save and restore" |

Off by default in both, for the same reason: a saved screen can hold secrets, tokens and command output, so treat the state directory the way you treat shell history |
| themes (12) + custom tokens | ✅ | ✅ | all 12 built-in themes plus `[theme.custom]` token overrides; `auto_switch` follows the terminal's light or dark mode on tmux 3.6 and later, with a terminal that reports it (see "Structural gaps") |
| named sessions, detach/attach, ssh attach | tmux itself, and `taw app` for the machines you name | ✅ | sessions, detach and attach are tmux's own job; `taw app` lists every machine's sessions in one list and puts the terminal on that machine's own tmux, over your ssh (README, "Remote machines") |

## Popup ledger

Each interaction herdr's sidebar (or tmux-session-wizard's popup) offers, and what it
is here. "kept" means the capability survived the redesign unchanged in substance.

| goto picker, workspace picker | `/` filter | kept; herdr's Go To shows every agent and terminal as a row of its own since v0.9.2 (#4384), as the tree always has. Go To's state keys (`b`, `w`, `i` and `d`, with `a` for every agent) are the state word typed into the filter here, `/blocked`, since `a` to `e` name rows. Go To's Left and Right, which jump between workspaces, are not taken ("Known divergences") |
| navigate workspace up/down | `J` / `K` | kept |
| new / rename / close workspace, close pane | `n`, `r` on a header, `x` on a header, `x` | kept |
| rename agent | `r` on an agent row, then `a` | kept |

| settings, help | `o`, `?`; the search preset binds neither, so there they are reached only through `[keys]` | kept |

| toast in herdr's own window | the tmux status line, which shows taw's bar while the popup is open; a toast lands in it as always | n/a |
| a key that shows or hides the preview | `[ui] preview` only | no key: the config turns the preview on or off, and it is drawn while the popup is 100 columns or wider |
| session-wizard: sessions or windows list, zoxide, create-or-switch, `zoxide add` | `[ui] depth`; the `n` picker's three sources; `Enter` | covered. | session-wizard: naming modes | `[sessions] name`, applying tmux's `.`/`:` rule instead of session-wizard's lowercasing; running-ness decided by path | covered, deliberately less strict: lowercasing merges directories tmux would keep apart |

each with the reason.

| A second agent started in a pane whose agent died | once the new agent's 3 s grace is over, herdr reads the whole screen, which still holds the frame the last agent left (a permission prompt read as the new agent's `blocked`, with a request toast), until the new agent draws over it | `taw agent start` records the line it typed the command on (`@agent_typed_line`), and the verb and the watcher read only the rows below it while it is on the screen, so the pane says `unknown` until the new agent draws there, and an install's progress or a transient prompt's rewrite counts as nothing of the agent | a person told that an agent that is only starting needs them is the worse mistake, and what the command started can draw nowhere else. An agent started by hand gets herdr's reading |
| Report order (`--seq`) | herdr keeps the numbers a source sent for a pane until the agent's process exits, and, for an agent it cannot name by its process, after the pane's shell has come back too; its metadata reports are ordered by a sequence of their own, with expiry | taw orders `pane report-agent`, `report-agent-session` and `release-agent` by herdr's rule (the row of v0.9.2 above) and forgets a source's numbers whenever the pane's agent leaves it, whichever way it leaves. `report-metadata` accepts `--seq` and ignores it: a later report replaces an earlier one | taw keeps the numbers with the agent's record, which is what it clears when an agent leaves, and its metadata options have no expiry or layers of sources for an order to be kept between |
| A restored pane whose saved directory is gone, once an agent comes to it | herdr keeps the pane's `restore_error` and its saved directory until the pane is closed; nothing can start in the pane, which has no shell, and a session an agent reports for it replaces the one it saved, in that saved directory | taw takes the error off, and saves the pane as it is (its folder now, its agent and session) once an agent of its own is recorded in it: the watcher names one in front of it, `taw agent start` starts one, or an agent reports its state or session | a taw pane is a shell, in which an agent can start in another folder, and kept as it was saved, its new conversation would be written over at every save by the one the pane had before, and lost to the next restore. A shell that goes to another folder, or a program that is no agent, ends nothing |
| Left and Right in the popup | herdr's Go To jumps to the first row of the previous or next workspace with Left and Right, without wrapping, except while a search is being edited (v0.9.2, #4384) | in the modal preset Left and Right do nothing; `J` and `K` move between sessions, and `[keys]` can bind the same moves (`next_workspace`, `previous_workspace`) to Left and Right | not ported: `J` and `K` already do it, and the search preset's query and the filter keep Left and Right for the cursor |
| A new session reported by an agent already in the pane | herdr takes a different session id from the same source for the same agent only when the report's session start reason is one that source may replace a session with (`session_report_allows_session_replacement`, `src/terminal/state.rs`, v0.9.3): Claude's `clear`, `resume` or `compact`, Codex's `startup`, `clear`, `resume` or `compact`, Pi's `new`, `resume` or `fork`, Grok's `new`, OpenCode's `select`, and so on per source; any other reason is dropped | every session report replaces the pane's session, whatever its start source, which is recorded on the pane (`@agent_token_session_start_source`). The one place the start source is read is an OpenCode `select` report with no `--seq`, which skips the order check (`unsequenced_selection`, `src/cli/pane/report.rs`, herdr's `is_unsequenced_opencode_selection`); herdr's rule that each source may replace a session only for some start reasons is not ported | not ported: a Claude `startup` or `fork` report over a session the pane already holds, which herdr drops, moves the pane to the new session here |
| `completion_seq` on `agent get` and `agent list` | an agent record carries `completion_seq`, a number set while the agent's current `idle` completed work, whoever has looked at it since, and `null` otherwise | not in taw's agent records | not ported: `done` and `@agent_seen` answer whether a turn ended unseen, and a client that needs to tell two completions apart reads `state_change_seq` (the time of the last state change here) |

## Structural gaps

One row each: what herdr does, why tmux cannot express it, and the closest thing you
can do instead. None of these is a missing implementation; the Linux shutdown save and the bundled sound files are choices taw made, said as such.

| Gap | Why tmux cannot | Workaround |
|---|---|---|
| Socket API (`HERDR_SOCKET_PATH`, JSON-RPC), `events.subscribe`/`events.wait` streaming, `terminal.attach`/`observe` | herdr is a server with a live control channel. `taw` is a binary that runs, reads tmux, and exits: there is no process to hold a subscription open, and adding a daemon would mean a second source of truth, which is exactly what the "tmux is the database" rule exists to prevent | 81 of herdr's 102 socket methods are CLI verbs returning the same JSON (`docs/COMPAT.md` lists the other 21 and why), so call or poll them. For pushed events, plugin `[[events]]` hooks carry the same 19 event names, delivered as a process launch instead of a stream. For raw terminal bytes, `taw pane read` (`capture-pane`) and tmux's own `pipe-pane` |
| Always-on sidebar, floating toasts | herdr *is* the renderer, so it can keep a panel and a toast drawn over live pane content. tmux below 3.8 has no surface that stays drawn over a pane; `display-popup` is modal: a key opens it, and it closes again | The popup for the whole sidebar, plus `#{@agent_wizard_status}` in your status line as the small always-visible summary. tmux 3.8's floating panes are the surface this actually needs; revisit when they are broadly available, not before |
| Toast screen position (`ui.toast.herdr.position`) | `tmux display-message` draws on the status line, wherever that is, and takes no position argument | Move the status line itself (`set -g status-position top`), or pick `ui.toast.delivery = "terminal"`/`"system"`, where the terminal or the OS notifier owns placement |
| Kitty graphics in a pane | herdr renders the standard Kitty graphics an app writes to its terminal (since v0.9.2, which removed its own `pane.graphics.*` methods). tmux multiplexes a pane's bytes and reflows its cells, and does not draw Kitty graphics itself | `set -g allow-passthrough on` lets an agent's *own* escape sequences reach a graphics-capable outer terminal, so an image a tool prints can still appear, but tmux does not track it with the pane's cells |
| Clearing a pane's screen (`pane.clear`) | herdr owns the terminal, so it drops a pane's screen and scrollback and keeps the cursor's line, for any program on the main screen, sending it nothing. tmux owns it here and has no command that clears a pane's screen: `clear-history` drops the scrollback only, and `send-keys -R` resets the pane's terminal, which undoes the modes the program set | `taw pane clear` clears the history of any pane off the alternate screen, and asks the pane's own shell for the screen: Ctrl-L to a bash, zsh or fish at its prompt, which clears it and draws its prompt and the line being typed at the top. Another program keeps its screen: clear it from inside the program |
| Remote attach with local keybindings, image paste | herdr's client speaks its own protocol, so it renders and intercepts keys on whichever machine you are sitting at, and carries a pasted image. taw closes both halves differently: the machine's own tmux gets the terminal, so its keys are its own, and `ctrl-v` on an agent's row of the list in the default preset, or paste image in the row's right-click menu (or `taw image paste --pane <id> --machine <name>`) sends the image on this machine's clipboard over that machine's ssh, where it is written to a file whose path is pasted into the agent as a bracketed paste (Claude Code and Codex attach it); an agent that is waiting on a question is asked to be answered first, and leaving the screen never waits for a paste under way. What is left is a gap: an ssh'd-in tmux client is a plain terminal on a pty, so the agent's own image paste key there reads that machine's clipboard, a machine's keys are not forwarded into the outer app, and a machine is saved in `config.toml`, not by a command | Map the chords in your local terminal emulator, before they leave the machine: WezTerm's `cmd_to_tmux_prefix`, for instance, turns local `cmd` chords into prefix sequences. For an image, `ctrl-v` on the agent's row in the popup or the app (or paste image in its right-click menu) |
| Mouse-first layout (dragging tabs and workspaces to reorder them) | the same client-rendering gap. herdr resolves every click and drag against its own layout, so it reorders tabs and workspaces when you drag them (its 0.4.7 and 0.4.0 releases). tmux's mouse keys are a table of bindings with a small default set: click a status-line window to select it, drag a border to resize, right-click for a menu, and in tmux 3.8 Alt-drag a pane to move it. A drag on the status line does nothing until you bind it | tmux's own mouse mode for select, resize, menus and (3.8) moving a pane, and `taw layout apply` / `taw pane swap` / `taw pane move` for the rearrangement itself |
| `theme.auto_switch` / `dark_name` / `light_name` | closed on tmux 3.6 and later, with a terminal that reports its light or dark mode: tmux's `#{client_theme}` says it per client, and the popup and `taw app` inside tmux draw `dark_name` or `light_name` from it. What is left is a gap only where the mode is unknown: an older tmux, a terminal that does not report it, or a client attached inside another tmux, which never gets the answer; the theme is then `name` | On such a setup let your OS appearance hook write `[theme] name` into the config file (`taw config path` locates it). The popup and `taw app` read the config when they start, so a changed theme shows in the next popup you open (and the next `taw app`). `taw config check` warns when `auto_switch` is on and the tmux is older than 3.6 |
| Live update handoff | herdr can hand its live panes to a new server as it updates (`herdr update --handoff`, opt-in and experimental) | n/a: tmux keeps panes alive independently of `taw`, so there is nothing to hand off. Replace the binary whenever you like. The pane watchers keep running the one they started with until they are started again: `taw watch status` marks them and `taw watch attach-all --restart` does it |
| `update.channel` / `update.version_check` | herdr updates itself from a release channel | n/a: TPM updates the plugin, and a `taw` the plugin downloaded follows it (the version that goes with the new checkout, fetched in the background); one you build with `scripts/install.sh` is yours to rebuild. Accepted and ignored so a herdr config parses |
| `[remote]` / `[server]` (`manage_ssh_config`, server lifecycle) | these configure herdr's own daemon and its ssh multiplexing | n/a: the tmux server *is* the server, and other machines are listed under `[machines]` (see "Saved machines" above). Accepted and ignored: `taw config check` names their keys as unknown |
| Save before a Linux shutdown (logind's delay lock) | herdr takes a logind delay lock, so its save runs before the system goes down. taw has no process that outlives the tmux server: a save is a `taw` call, and the hooks that make one stop with the server | The autosave hooks and the 5 second wait on close keep the layout from the last change, and the copies in `session-snapshots/` hold older ones. `taw session save` before you shut down, or a `systemd` unit of your own that runs it |
| Bundled sound files | herdr plays its own completion chime and request alert, and takes your mp3 files as overrides | `[ui.sound]` takes paths to your own files, played through `afplay`/`paplay`/`aplay`. Nothing is bundled, so a sound that is configured but missing is a no-op rather than an error |

## Pinned

Neither parity nor a gap: recorded so nobody reopens them by accident. A row that has
since been resolved stays here, marked, rather than disappearing, since the reasoning is
what stops it being reopened.

| Item | Why it is pinned |
|---|---|
| Workspace ordering (`workspace.move`, `workspace.move_block`) | **Closed: not needed.** tmux has no session-order primitive: `list-sessions` order is not settable, and a session's numeric id is fixed at creation, so a `taw`-owned order would be one only the popup honoured while `tmux list-sessions` and the status line kept the real one. The question it would answer is answered another way. The tree is tmux's order, always, and "which one first" is instead answered by attention: `Tab` walks what needs you, across every session, and the cursor opens on the pane you came from. There is nothing left for a manual ordering to do, so this is closed rather than pinned |
| Windows | tmux does not build or run on Windows, so there is no tmux there for `taw` to observe. Out of scope, not a defect |
